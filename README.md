## Окружение

- **Операционная система:** CentOS Linux 7 (Core)
- **Ядро:** Linux 3.10.0-1160.el7.x86_64
- **Загрузчик:** GRUB2
- **Initramfs:** `initrd` / `initramfs`
- **Виртуализация:** VirtualBox (или другая система виртуализации)
- **LVM:** используется для управления дисковой разметкой

# Загрузка Linux и редактирование параметров GRUB

Для изменения параметров загрузки необходимо открыть графический интерфейс VirtualBox (или другой системы виртуализации), запустить виртуальную машину и во время выбора ядра Linux нажать **`e`** (`edit`).

После этого открывается конфигурация загрузки GRUB2:

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/e78da366-b435-4c4a-8c90-33d41a3741fa" />

Основные параметры загрузки находятся в строке, начинающейся примерно так:

```text
linuxefi /vmlinuz-... root=... ro ...
```

В эту строку можно временно добавить или изменить параметры ядра.

Для запуска с изменёнными параметрами используется:

```text
Ctrl + X
```

Изменения, сделанные таким способом, являются временными и относятся только к текущей загрузке.

# Получение доступа к системе без пароля

## Способ 1 — `init=/bin/sh`

В конце строки, начинающейся с `linuxefi`, добавляем:

```text
init=/bin/sh
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/bee40a91-42a5-46b1-8898-649083405fe3" />

и запускаем систему:

```text
Ctrl + X
```

### Что означает `init=/bin/sh`

Параметр:

```text
init=/bin/sh
```

передаёт ядру Linux указание использовать `/bin/sh` в качестве первого пользовательского процесса (`PID 1`) вместо обычной программы инициализации системы.

Обычно процесс загрузки после запуска ядра передаёт управление `init`/`systemd`. При использовании `init=/bin/sh` вместо обычной последовательности запуска непосредственно запускается оболочка:

```text
/bin/sh
```

Это позволяет получить командную строку на раннем этапе загрузки системы.

> Важно: этот способ предоставляет очень низкоуровневый доступ к системе и не является обычным режимом загрузки.

### Корневая файловая система

В данном режиме корневая файловая система может быть смонтирована в режиме **Read-Only**.

Проверить режим монтирования:

```bash
mount | grep root
```

Чтобы перемонтировать `/` в режим записи:

```bash
mount -o remount,rw /
```

После этого файловая система становится доступной для записи:

# Способ 2 — `rd.break`

В конце строки, начинающейся с `linuxefi`, добавляем:

```text
rd.break
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/a1e7ea4a-17f6-4aab-b828-57ebe73cefe6" />

После этого:

```text
Ctrl + X
```

### Что означает `rd.break`

`rd.break` — параметр, предназначенный для остановки процесса загрузки внутри **initramfs**.

В результате система попадает в emergency shell ещё до обычного запуска установленной системы.

При этом корневая файловая система установленной системы обычно доступна через:

```text
/sysroot
```

Однако сама файловая система смонтирована в режиме **Read-Only**, поэтому сначала необходимо разрешить запись:

```bash
mount -o remount,rw /sysroot
```

После этого можно перейти в установленную систему:

```bash
chroot /sysroot
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/18bf1c79-33d3-4ae3-8771-c20dbd33b1b7" />

### Что делает `chroot`

Команда:

```bash
chroot /sysroot
```

изменяет корневой каталог (`/`) для текущего процесса и его дочерних процессов.

До выполнения `chroot` мы находимся в окружении `initramfs`, а после:

```text
chroot /sysroot
```

команды работают относительно установленной на диске системы.

Например, можно изменить пароль `root`:

```bash
passwd root
```

При использовании SELinux после изменения важных системных файлов можно создать файл:

```bash
touch /.autorelabel
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/436253bc-037e-4971-be6e-b1295853ae6c" />

При следующей загрузке система выполнит переиндексацию SELinux-контекстов.

Можно перезагрузить систему.

# Способ 3 — `rw init=/sysroot/bin/sh`

В строке, начинающейся с `linuxefi`, заменяем:

```text
ro
```

на:

```text
rw init=/sysroot/bin/sh
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/a83ff96d-6212-4efa-93ec-07ddc3dc7549" />

После этого:

```text
Ctrl + X
```

В результате корневая файловая система сразу монтируется в режиме **Read-Write**, а в качестве запускаемого процесса используется shell из установленной системы:

```text
/sysroot/bin/sh
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/b37338b1-32d7-4762-9769-0e9da8d14138" />

Таким образом, этот способ похож на предыдущие варианты, но позволяет сразу получить оболочку с файловой системой в режиме записи.
