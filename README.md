# Практические навыки загрузки Linux

Практическая работа посвящена загрузке Linux, восстановлению доступа к системе без знания пароля администратора, работе с LVM и созданию собственного модуля для `initrd`.

## Окружение

- **Операционная система:** CentOS Linux 7 (Core)
- **Ядро:** Linux 3.10.0-1160.el7.x86_64
- **Загрузчик:** GRUB2
- **Initramfs:** `initrd` / `initramfs`
- **Виртуализация:** VirtualBox (или другая система виртуализации)
- **LVM:** используется для управления дисковой разметкой

# Загрузка Linux и редактирование параметров GRUB

Для изменения параметров загрузки необходимо открыть графический интерфейс VirtualBox (или другой системы виртуализации), запустить виртуальную машину и во время выбора ядра Linux нажать **`e`** (`edit`).

После этого открывается конфигурация загрузки GRUB2:

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/e78da366-b435-4c4a-8c90-33d41a3741fa" />

Основные параметры загрузки находятся в строке, начинающейся примерно так:

```text
linuxefi /vmlinuz-... root=... ro ...
```

В эту строку можно временно добавить или изменить параметры ядра.

Для запуска с изменёнными параметрами используется:

```text
Ctrl + X
```

Изменения, сделанные таким способом, являются временными и относятся только к текущей загрузке.

# Получение доступа к системе без пароля

## Способ 1 — `init=/bin/sh`

В конце строки, начинающейся с `linuxefi`, добавляем:

```text
init=/bin/sh
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/bee40a91-42a5-46b1-8898-649083405fe3" />

и запускаем систему:

```text
Ctrl + X
```

### Что означает `init=/bin/sh`

Параметр:

```text
init=/bin/sh
```

передаёт ядру Linux указание использовать `/bin/sh` в качестве первого пользовательского процесса (`PID 1`) вместо обычной программы инициализации системы.

Обычно процесс загрузки после запуска ядра передаёт управление `init`/`systemd`. При использовании `init=/bin/sh` вместо обычной последовательности запуска непосредственно запускается оболочка:

```text
/bin/sh
```

Это позволяет получить командную строку на раннем этапе загрузки системы.

> Важно: этот способ предоставляет очень низкоуровневый доступ к системе и не является обычным режимом загрузки.

### Корневая файловая система

В данном режиме корневая файловая система может быть смонтирована в режиме **Read-Only**.

Проверить режим монтирования:

```bash
mount | grep root
```

Чтобы перемонтировать `/` в режим записи:

```bash
mount -o remount,rw /
```

После этого файловая система становится доступной для записи:

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/301841a1-3840-4cca-9cbd-a0b2ea216985" />

# Способ 2 — `rd.break`

В конце строки, начинающейся с `linuxefi`, добавляем:

```text
rd.break
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/a1e7ea4a-17f6-4aab-b828-57ebe73cefe6" />

После этого:

```text
Ctrl + X
```

### Что означает `rd.break`

`rd.break` — параметр, предназначенный для остановки процесса загрузки внутри **initramfs**.

В результате система попадает в emergency shell ещё до обычного запуска установленной системы.

При этом корневая файловая система установленной системы обычно доступна через:

```text
/sysroot
```

Однако сама файловая система смонтирована в режиме **Read-Only**, поэтому сначала необходимо разрешить запись:

```bash
mount -o remount,rw /sysroot
```

После этого можно перейти в установленную систему:

```bash
chroot /sysroot
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/18bf1c79-33d3-4ae3-8771-c20dbd33b1b7" />

### Что делает `chroot`

Команда:

```bash
chroot /sysroot
```

изменяет корневой каталог (`/`) для текущего процесса и его дочерних процессов.

До выполнения `chroot` мы находимся в окружении `initramfs`, а после:

```text
chroot /sysroot
```

команды работают относительно установленной на диске системы.

Например, можно изменить пароль `root`:

```bash
passwd root
```

При использовании SELinux после изменения важных системных файлов можно создать файл:

```bash
touch /.autorelabel
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/436253bc-037e-4971-be6e-b1295853ae6c" />

При следующей загрузке система выполнит переиндексацию SELinux-контекстов.

Можно перезагрузить систему.

# Способ 3 — `rw init=/sysroot/bin/sh`

В строке, начинающейся с `linuxefi`, заменяем:

```text
ro
```

на:

```text
rw init=/sysroot/bin/sh
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/a83ff96d-6212-4efa-93ec-07ddc3dc7549" />

После этого:

```text
Ctrl + X
```

В результате корневая файловая система сразу монтируется в режиме **Read-Write**, а в качестве запускаемого процесса используется shell из установленной системы:

```text
/sysroot/bin/sh
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/b37338b1-32d7-4762-9769-0e9da8d14138" />

Таким образом, этот способ похож на предыдущие варианты, но позволяет сразу получить оболочку с файловой системой в режиме записи.

# LVM: переименование Volume Group

Для начала посмотрим текущее состояние LVM:

```bash
vgs
```

Пример:

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/0bb2b1bd-6257-4f47-bbdf-5f8f51cbc826" />

Нас интересует имя **Volume Group (VG)**:

```text
centos
```

Переименуем его:

```bash
vgrename centos testing
```

Ожидаемый результат:

```text
Volume group "centos" successfully renamed to "testing"
```

Проверяем:

```bash
vgs
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/eb7ac1dd-831c-4cad-89b8-216d64938300" />

# Что такое LVM

**LVM (Logical Volume Manager)** — механизм управления дисковым пространством в Linux.

Основные элементы LVM:

```text
Physical Volume (PV)
        │
        ▼
Volume Group (VG)
        │
        ├── Logical Volume (LV)
        └── Logical Volume (LV)
```

В рассматриваемом примере:

```text
PV → centos → LV
```

после переименования:

```text
PV → testing → LV
```

Изменение имени VG важно учитывать во всех местах, где старое имя используется для поиска корневой файловой системы.

# Пересоздание initrd после изменения LVM

После переименования Volume Group необходимо проверить конфигурацию системы и заменить старое имя VG на новое там, где оно используется для загрузки и монтирования корневой файловой системы.

В данной конфигурации CentOS 7 используется загрузка **UEFI**, поэтому конфигурация GRUB находится в:

```text
/boot/efi/EFI/centos/grub.cfg
```

Необходимо проверить следующие файлы:

```text
/etc/fstab
/etc/default/grub
/boot/efi/EFI/centos/grub.cfg
```

Например, если VG был переименован:

```text
centos → testing
```

то ссылки на старое имя необходимо заменить на новое:

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/1ea7720c-0183-489d-9186-6c61d5c1f04f" />

Особое внимание следует обратить на параметры `rd.lvm.lv` в конфигурации GRUB. Например:

```text
rd.lvm.lv=centos/root
```

после переименования VG должен указывать на новое имя:

```text
rd.lvm.lv=testing/root
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/2e52a98d-1003-41b3-bde2-c4b0b095a796" />

После изменения конфигурации необходимо пересоздать образ `initramfs`, чтобы он содержал актуальную информацию, необходимую для обнаружения и активации LVM при загрузке системы:

```bash
mkinitrd -f -v /boot/initramfs-$(uname -r).img $(uname -r)
```

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/4bb636b3-e6c3-4590-82a1-6d426faa57bd" />

После этого можно перезагрузить систему и проверить:

```bash
vgs
```

При необходимости аналогичным образом можно изменить название **Logical Volume (LV)**.

---

### Почему необходимо обновлять и GRUB, и initramfs

При загрузке используются несколько последовательных компонентов:

```text
GRUB
  │
  │ параметры ядра, включая rd.lvm.lv
  ▼
Linux kernel
  │
  ▼
initramfs
  │
  │ обнаружение и активация LVM
  ▼
Root filesystem
  │
  ▼
запуск системы
```

Если в GRUB останется старое имя VG, ядро получит устаревший параметр `rd.lvm.lv`, даже если `initramfs` уже пересобран.

В результате загрузка может остановиться в `dracut`, поскольку система не сможет найти указанный LVM-том.

# Добавление собственного модуля в initrd

Модули `dracut` находятся в каталоге:

```text
/usr/lib/dracut/modules.d/
```

Создадим собственный модуль:

```bash
mkdir /usr/lib/dracut/modules.d/01testing
```

В каталоге создаются два скрипта:

```text
/usr/lib/dracut/modules.d/01testing/
├── module-setup.sh
└── test.sh
```

### `module-setup.sh`

Этот скрипт сообщает `dracut`, как установить модуль в `initrd` и какой скрипт необходимо выполнить.

Общая идея:

```text
module-setup.sh
        │
        └── подключает test.sh
```

### `test.sh`

Это непосредственно выполняемый скрипт:

<img width="1023" height="768" alt="изображение" src="https://github.com/user-attachments/assets/d86caccd-3e69-48ee-bd16-c72f1c0447a4" />

# Пересборка initrd

После создания собственного модуля необходимо пересобрать образ `initrd`.

Вариант с `mkinitrd`:

```bash
mkinitrd -f -v /boot/initramfs-$(uname -r).img $(uname -r)
```

Или с помощью `dracut`:

```bash
dracut -f -v
```

# Полезные пояснения

## `ro` и `rw`

Параметры:

```text
ro
rw
```

определяют режим монтирования корневой файловой системы.

- `ro` — **Read-Only**, только чтение.
- `rw` — **Read-Write**, чтение и запись.

Например:

```text
root=/dev/mapper/centos-root ro
```

означает, что корневая файловая система при загрузке первоначально монтируется только для чтения.

---

## `init=/bin/sh`

```text
init=/bin/sh
```

указывает ядру использовать `/bin/sh` как первый пользовательский процесс вместо стандартной системы инициализации.

Практически это позволяет получить shell на раннем этапе загрузки.

---

## `rd.break`

```text
rd.break
```

останавливает загрузку внутри `initramfs` и предоставляет emergency shell.

При этом установленная система обычно доступна через:

```text
/sysroot
```

---

## `chroot`

```bash
chroot /sysroot
```

меняет корневой каталог для текущего окружения.

Это позволяет выполнять команды так, как будто `/sysroot` является обычным `/`.

---

## `initrd` / `initramfs`

`initrd` (initial RAM disk) / `initramfs` — временная файловая система, используемая на раннем этапе загрузки Linux.

Она содержит необходимые программы, модули ядра и конфигурацию, позволяющие подготовить систему к переходу на настоящую корневую файловую систему.

Упрощённая последовательность загрузки:

```text
BIOS/UEFI
   │
   ▼
GRUB2
   │
   ▼
Linux kernel
   │
   ▼
initramfs
   │
   ├── обнаружение устройств
   ├── загрузка необходимых модулей
   ├── подготовка LVM/RAID/дисков
   └── поиск корневой ФС
   │
   ▼
root filesystem
   │
   ▼
systemd / init
   │
   ▼
запуск системы
```

# Итог

Рассматриваются три важных направления администрирования Linux:

1. **Загрузка и восстановление доступа**

   * редактирование параметров GRUB;
   * `init=/bin/sh`;
   * `rd.break`;
   * `chroot`;
   * изменение режима `ro` → `rw`.

2. **Работа с LVM**

   * просмотр VG с помощью `vgs`;
   * переименование Volume Group через `vgrename`;
   * обновление конфигурации загрузки;
   * пересоздание `initrd`.

3. **Работа с initrd/initramfs**

   * структура модулей `dracut`;
   * создание собственного модуля;
   * добавление скриптов в initrd;
   * проверка содержимого через `lsinitrd`;
   * проверка выполнения скрипта во время загрузки.

Ранние этапы загрузки Linux позволяют выполнять диагностику и восстановление системы ещё до запуска обычного пользовательского окружения.
